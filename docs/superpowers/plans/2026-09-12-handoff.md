## Carried forward — new since 2026-09-11

### Not every shared name follows the owning-module rule

The 2026-09-11 rule ("patch the module that CALLS a name") is about imported *functions*,
which are rebound per namespace. `METRIC_TABLES` is one dict shared by identity across every
importer — same `id()` in `app`, `goals`, `metrics`, `export_routes`. So:

- `monkeypatch.setitem`/`delitem` on `metrics.METRIC_TABLES` reaches every consumer.
- `monkeypatch.setattr(app_module, "METRIC_TABLES", shrunk)` reaches **only** `app.py`'s
  validation, and silently leaves goals on the full mapping.
- A per-module owner fixture for it is scaffolding, and an identity-comparison guard like
  `no_real_garmin_client` cannot detect a desynced patch on a shared dict at all.

Check which kind a name is before reaching for the fixture pattern. `metrics.py`'s docstring
carries the instruction.

### Ancestry does not prove a branch was merged

Eight of the 22 pruned branches (#25–#31, #33) were squash-merged, so `git merge-base
--is-ancestor` called them unmerged and `git diff main...branch` showed each as hundreds of
lines of "unmerged work" — three-dot shows the branch's own additions since the merge base
whether or not `main` has them. What establishes safety before a delete is PR state
(`gh pr list --head <branch> --state all`) plus a content spot-check under the *current* path
(these predate the #47 rename).

### Docstrings describe their own module's contract

The convention itself is in the 2026-09-11 handoff (added by #56). The short version: ask
**who can falsify this sentence?** If a change in another module can, it's in the wrong file
or should be a present-tense constraint rather than an account. Four instances were found
this run — two in the goals branch, two pre-existing (`CLAUDE.md`'s line-range pointer and
`conftest.py`'s "hyphenated directory" rationale). The pre-existing conftest one is the
insidious kind: `importlib` kept working after the rename, so nothing failed, so nobody
checked, and the suite carried both idioms side by side for weeks.

## Things I got wrong, recorded so they are not re-derived

1. **I mutation-verified the degrade guard *before* moving it**, so the mutation tested
   `app._goal_progress` — code that no longer existed at that location. The reviewer re-ran it
   in `goals.progress_for_goal`. Re-mutate in the shipped location after any move.
2. **I diagnosed `METRIC_TABLES` patching as the by-value trap and built a fixture plus a
   mutation-verified test on that theory.** Wrong kind of name (see above). The test was also
   brittle: `goals.py` switching to `import metrics` would be identical behaviour and break the
   assertion — it pinned import style, not behaviour. A mutation-verified test can still be
   testing the wrong property.
3. **`assert progress is not None` passed vacuously.** A valid metric with no rows yields a
   `GoalProgress` of all-Nones — an object, not `None`. Assert a value.
4. **I wrote an aspirational docstring** ("sorted here so the ordering cannot drift between
   routes") that nothing enforced — the exact defect class the branch existed to fix, one
   level down.
5. **I asserted a cause I hadn't verified** ("which is why this was originally recorded as
   fully cleaned up") in #54's first draft. The handoff's own rule 5 is "check before
   defending." Dropped before merge.
6. **I ran the same command twice and called it a mutation test.** Caught it on the next line;
   the real mutation followed. A "mutation" that changes nothing proves nothing.
7. **`set -e` + `grep -c "(healthy)"` killed my prod health-wait on iteration one** — `grep
   -c` exits 1 on a count of zero, which is precisely the "not yet" state. Use `|| true`. The
   containers were fine.
8. **I acted on two reviewer/advisor claims that were false**: that `CLAUDE.md` has an
   owning-module note (it doesn't), and that `import_service_module` couldn't be deleted
   because two sites were dynamic (one restructures to module objects, the other calls stdlib
   directly). Both were caught by checking. A reviewer's claim about the codebase is a claim.

## Carried forward — read before changing either service

### The owning-module rule (the one thing most likely to bite you)

Both services now spread their code over several modules. Garmin helpers, `get_db`,
`fit_import` and friends are bound into **each module's own namespace** by
`from x import y`. That means:

> **Patch the module that CALLS a name, not the module that DEFINES it.**

`tests/conftest.py` has fixtures for exactly this: `activity_garmin_module`,
`activity_routes_module`, `weight_routes_module`, `garmin_claim_module`,
`dashboard_export_module`, `dashboard_fit_module`. Their docstrings say which is which.

Getting it wrong does not fail loudly in every case. The dangerous shape is patching a
binding no route reads — the test passes having exercised the **real** code path. Two
guards exist:

- `no_real_garmin_client` asserts per owning module, with a `hasattr` check so a future
  move fails loudly rather than silently checking nothing.
- `tests/test_auth_split.py` fails if any name tests monkeypatch on `shared.auth` is
  imported by value into `shared/auth_routes.py`. `_authenticate_credentials` and
  `_require_step_up` are reached through the module for this reason.

### Parity gates for any route refactor

Route table **and** OpenAPI schema, captured before and diffed after. Both were
byte-identical for every split in this run, on both services. A change to anything under
`shared/` must be checked on **both** services, not just the one you were thinking about.

```python
import importlib, json
m = importlib.import_module("vitalforge_weight.app")   # and vitalforge_dashboard.app
sorted((r.path, tuple(sorted(r.methods or []))) for r in m.app.routes)
json.dumps(m.app.openapi(), sort_keys=True, indent=1)
```

### Deploying

Merging builds and pushes images. **Nothing deploys them.** On `192.168.1.21`:
`cd /home/user/docker/vitalforge && docker compose pull && docker compose up -d`.

Take a snapshot first — additive `_add_columns` / `CREATE TABLE` changes do **not** fire
`ensure_pre_migration_snapshot`, so nothing backs up on its own:

```bash
docker exec vitalforge-vitalforge-weight-1 python -c \
  'import sqlite3; sqlite3.connect("/app/data/fitness.db").execute("VACUUM INTO ?", ("/app/data/pre.db",))'
docker cp vitalforge-vitalforge-weight-1:/app/data/pre.db /home/user/docker/vitalforge/backups/
```

`VACUUM INTO`, not a tar of the live file — the WAL makes a tar potentially torn. There
are 8 snapshots in `backups/` now; prune them at some point.

### Things that look like the directory name but are not

Renaming the service directories (#47) did **not** touch, and you must not touch:
compose service keys (`vitalforge-weight:`), CI matrix `name:` values (they become the
pushed image tags prod pulls), `/health` service strings (deploy checks grep them),
`sw.js` `CACHE_NAME` (changing it busts every client's PWA cache), and
`pyproject.toml`'s `packages = ["shared"]` — each Dockerfile runs `pip install -e .`
**before** copying its service directory, so listing the services breaks the image build.

## Conventions this run established

- **Mutation-verify every fix.** Revert the fix, confirm the test goes red, restore. Every
  behavioural fix in #41/#43/#45/#52 was checked this way. A green test that has never
  been seen to fail is not evidence.
- **Route + OpenAPI parity** as the gate for refactors claiming no behaviour change.
- **`tests/test_module_size.py`** enforces the 800-line ceiling with **no exemptions**. Add
  a named entry with a reason, never raise the limit to make a build green.
- **Guard the class, not a proxy metric.** After the stderr log landed, the CI check greps
  for tracked scratch paths rather than capping diff size — #42 was a legitimate
  4,916-insertion PR, so a size cap would cry wolf and still miss a small stray log.
  Verified both directions: passes clean, and flags the exact commit that caused it.
- **Snapshot before every deploy.**

## Things I got wrong, recorded so they are not re-derived

   from luck on an intermittent bug — stress it.
2. **`git add -A` put 11,576 lines of Codex stderr on `main`** (#43), through a rule this
   repo states explicitly. Stage paths.
3. **`git checkout <file>` to undo a mutation test destroyed uncommitted work, twice.** The
   second time I pushed a PR whose commit message described an `app.py` fix the commit did
   not contain; caught only by reading `git status --short` before the push. Restore from
   a `cp`, or commit before mutating — and diff the branch against base before opening a
   PR.
4. **The `/prp-plan` premise was wrong.** I claimed the hyphenated directory *blocked*
   splitting. It blocks `import` statements, but `vitalforge_dashboard/app.py` already
   worked around it with `sys.path.insert` + flat imports. The rename was still the better
   end state, but the user chose it partly on a claim that was not accurate.
5. **I deflected a review finding with a false claim about the codebase** — that
   cross-module test-helper sharing "is not this suite's pattern". 35 test modules import
   from `tests.conftest`. Check before defending.
6. **I guessed the deploy host was `atlas`** from a Tailscale name. It is `192.168.1.21`
   (`knowledge`). Corrected in memory.
7. **Two plan risks were mis-stated and corrected only after checking**: route shadowing
